## 오늘 한 일

- Metro 연결 트러블슈팅: `adb reverse tcp:8081` 유실 재연결, 포트 8081을 다른 프로젝트(power-nap)의 좀비 Metro가 재점유하는 기존 지뢰가 재발 → 사용자가 직접 프로세스 종료, CLAUDE.md에 "Nightcap의 Metro는 항상 8081 고정, 대체 포트로 안 넘어간다" 규칙 추가
- 실기기 도그푸딩 중 발견한 버그 수정: 공유 이미지의 `content_hash` 계산이 매번 조용히 실패하던 `expo-crypto`/`expo-file-system` ArrayBuffer 타입 불일치(`docs/troubleshooting/expo-crypto-digest-arraybuffer-attach.md`)
- 제품 이슈: 유튜브 등을 공유해도 카드 제목이 그냥 URL 그대로 떠서 "어떤 콘텐츠였는지" 알 수 없는 문제 확인 → "전부 로컬" 원칙에 **공개 URL의 공개 메타데이터(oEmbed/og 태그) 읽기만 허용**하는 좁은 예외를 먼저 CLAUDE.md에 명문화하고 나서 구현(`docs/decisions/url-metadata-fetch.md`)
  - `services/urlMetadata.ts` 신규: 유튜브 oEmbed 직행 → 그 외 도메인은 oEmbed 디스커버리 → `og:title`/`og:image` 파싱, 3초 타임아웃, 실패해도 조용히 기존 동작(URL 그대로)으로 폴백
  - 인스타/X는 로그인 벽으로 fetch가 거의 항상 막힘 → WebView/로그인 세션 재사용 스크래핑은 실효성·약관 리스크로 기각(문서화), 대신 URL 경로 패턴만으로 최소 라벨("릴스"/"게시물"/"X 게시물 · @handle") 부여
  - 카드는 INSERT 즉시 뜨고 메타데이터는 fire-and-forget 비동기로 나중에 title/이미지 UPDATE, 썸네일은 URL을 저장하지 않고 기존 샌드박스 사본 파이프라인으로 다운로드
- 후속 품질 개선 3건:
  1. HTML 엔티티 디코딩 버그 수정(`&#x4eac;` 등이 제목에 그대로 남던 문제) — `utils/htmlEntities.ts` 신규(숫자+주요 named entity, 라이브러리 없이), 마이그레이션 v5로 기존 저장분도 1회성 재정리
  2. `source_author` 컬럼 추가(마이그레이션 v4) — 유튜브(oEmbed `author_name`), 인스타(`og:title`의 `"{author} on Instagram: ..."` 패턴 분리), X(URL의 `@handle`, 로그인벽 우회용으로 fetch 성공 여부와 무관하게 우선 적용), 일반 웹(`og:site_name`). 카드/타일/상세 출처 줄을 "출처앱 · 게시자"로 통일
  3. 보관함 상세에 "원본 열기"(`Linking.openURL`, `source_url` 있을 때만, 정리 모드 카드엔 안 넣음) — 제목 편집도 `kind` 무관 전체 허용으로 확장(기존엔 DRM 카드만 가능했던 게 원래 누락)
- 사이드 이펙트로 발견해 같이 고침: `CoverImage` 컴포넌트가 세로 스크린샷 전용으로만 설계돼 있어 가로형 링크 썸네일이 타일 상단에 작게 뜨고 하단이 비던 버그(`docs/troubleshooting/coverimage-landscape-thumbnail-empty-space.md`) — 컨테이너/이미지 비율 비교로 크롭 방향(상단 vs 중앙)을 동적으로 판단하도록 일반화, 공용 컴포넌트라 4개 화면에 한 번에 적용됨
- `npx tsc --noEmit` 통과 확인, dev-client 디버그 APK 재빌드 없이 JS 변경만으로 Metro Fast Refresh 반영(네이티브 의존성 추가 없음)

## 오늘 배운 것

### `presentPermissionsPicker`는 Android에서 권한 재요청일 뿐이다

"전체 허용"이 아무 일도 안 하길래 네이티브를 열어봤다:

```kotlin
fun presentPermissionsPicker(...) { requestPermissions(...) }
```

별도의 사진 재선택 모달이 아니다. 사용자가 한 번 선택을 내린 뒤(`USER_SET`)엔 OS가 아무것도
안 띄우므로 **도움이 필요한 바로 그 상태에서 조용한 no-op**이 된다. SDK 문서의
"originally allowed only limited access" 조건이 이걸 말하는 것이었다.

지시서가 준 두 안 중 `openSettings` 단일화를 골랐다. 다른 안(400ms 뒤 재확인 후 폴백)은 판별
신호가 없어 타이밍 추정에 기대야 하고, 오탐하면 이미 열린 선택기 위에 시스템 설정이 겹쳐 뜬다 —
탭 몇 번보다 나쁜 실패다.

### 권한 상태는 테스트 방식이 결과를 바꾼다

`pm grant`로 만든 limited는 "사용자가 원래 허용한" 경로를 타지 않아 위 API가 안 열린다. 또
깨끗한 상태에서는 선택기를 취소하면 `none`이지만, 이미 `USER_SELECTED`가 있으면 `limited`가
유지된다. **조사 단계에서 "취소 = limited"라고 보고했던 걸 이 라운드에서 정정했다** — 앞선 관찰이
두 번째 경우였다.

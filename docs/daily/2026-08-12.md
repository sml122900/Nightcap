전날(2026-08-11) 밤에 구현한 보관함 다중 선택 삭제(A) + 상세 좌우 스와이프(B) 두 기능을
실사용자의 실제 보관함 데이터(16개)로 실기기 검증한 라운드. 코드 커밋은 전부 08-11 날짜로
남아 있고, 오늘은 검증과 문서 마감만 했다.

## 오늘 한 일

### A. 다중 선택 삭제 실기기 검증

- 길게 누르기 → 선택 모드(체크 배지) → 탭 토글 → 다중 선택 정상
- 별점 필터를 바꿔도 "N개 선택" 카운트 유지 확인 — 화면 밖으로 스크롤된 선택 항목도 살아있다
- 뒤로가기 → 선택 모드만 해제되고 보관함 화면 자체는 유지됨(화면 이탈 아님)
- 실데이터로 실제 삭제 1건 실행: 확인 다이얼로그("1개를 휴지통으로 이동") → 휴지통 1→2 →
  휴지통에서 항목 확인 → 복원 → 휴지통 2→1, 그리드 순서/개수까지 삭제 전과 완전히 동일하게 복귀
- 표본을 16개 중 1개로 최소화한 건 실사용 데이터를 건드리는 검증이라 되돌릴 수 있는 범위를
  좁게 잡았기 때문 — 지시서가 요구한 경로(선택→삭제→휴지통 반영→복원)는 1건으로도 동일하게 탄다

### B. 상세 좌우 스와이프 실기기 검증

- 페이징 순서가 보관함 그리드의 현재 필터/정렬 순서와 정확히 일치
- 스와이프 직후 빈 화면 없음(인접 카드 프리로드 확인, 4장 이상 연속 스와이프로 양방향 확인)
- 세로 스크롤(카드 하단 메타 영역)과 가로 페이징 충돌 없음. 단 텍스트 입력창에 포커스가 있는
  상태에서 그 입력창 위를 스와이프하면 텍스트 선택 제스처가 우선됨 — `TextInput`의 정상 동작이고
  다른 영역(이미지 등)에서 스와이프하면 문제없다
- 카드3에서 제목을 고쳐 카드4로 넘어갔다 돌아와도 카드3만 바뀌어 있음을 확인 — 카드별 편집이
  엉뚱한 카드에 안 묻는다는 지시서의 핵심 요구사항
- 첫 카드에서 계속 오른쪽으로 스와이프해도 크래시·순환 없이 첫 카드에 머묾(바운스)
- **별점 드래그는 adb로 검증 못 함** — 아래 "다음에 할 일" 참고, 제목 필드 편집으로 대체 검증

## 오늘 배운 것

### `input tap`은 Gesture Handler의 Pan을 활성화하지 못한다

별점 바를 adb로 직접 드래그해 보려다 막혔다. `input tap`은 정지 탭이라 Pan의 활성화/이동
임계값을 넘기지 못해 `onEnd`(=commit)가 아예 안 불린다. `input swipe`로 바꿔도, 좌표가
이미 포커스된 멀티라인 `TextInput` 위나 근처에 걸리면 텍스트 선택 드래그로 먹혀버려 페이저로
전파되지 않는다. 결국 카드별 편집 격리라는 검증 목적 자체는 제목 필드(`input text`로 안정적으로
조작 가능)로 대체해 증명했다 — 별점 값 자체의 손맛/정확도는 여전히 사람 손이 필요하다.

# 휴지통 조회를 image_uri 존재 여부가 아니라 deleted_at 시간창으로 필터

## Problem

PROJECT.md §8은 "휴지통은 7일간 보관"이라고만 명시했고, 처음 설계할 때는 "이미지가 아직 남아있는(=purge되지 않은) 항목만 휴지통에 노출"하는 게 자연스러워 보여 `getTrash()`를 `image_uri IS NOT NULL` 조건으로 필터하려 했다. 하지만 이 앱은 아직 실제 스크린샷 캡처 파이프라인이 없고 목데이터(`MOCK_CAPTURES`)는 애초에 `image_uri`를 절대 채우지 않는다는 걸 뒤늦게 인지했다. 그 필터를 그대로 쓰면 휴지통 화면이 이 단계에서는 **영구히 비어** 있어 기능 자체를 검증할 방법이 없어지는 자기모순이 생겼다.

## Action

Plan 단계에서 서브에이전트에게 설계를 교차검증시켜 이 문제를 미리 발견했고, 필터 기준을 `deleted_at IS NOT NULL AND deleted_at >= (now - 7일)`로 바꿨다. §1의 "7일 이내 삭제 항목을 복원할 수 있음"이라는 문구가 스펙상 더 정확한 기준이기도 하고, 목데이터든 실데이터든 동일하게 동작한다(`image_uri` 유무와 무관하게 시간 창 안에 있으면 노출, 창을 벗어나면 자동으로 안 보임).

## Result

- 목데이터만 있는 현재 단계에서도 휴지통 화면과 복원 플로우를 실제로 검증 가능
- 실제 캡처 파이프라인이 붙어 `image_uri`가 채워지기 시작해도 쿼리를 바꿀 필요 없음(설계가 미래 상태에도 그대로 맞음)
- "필터 조건 하나를 프로토타입 단계의 데이터 형태까지 고려해서 고른다"는 걸 구현 전 계획 리뷰에서 잡아낸 사례 — 코드 작성 후 QA에서 발견했다면 화면 하나를 통째로 다시 설계해야 했을 것

# SQLite 마이그레이션을 PRAGMA user_version 버저닝 시스템으로 구현

## Problem

휴지통/보관함 기능을 위해 처음으로 SQLite 영속화 계층을 도입해야 했다. 아직 배포된 스키마가 전혀 없는 상태(그동안은 메모리 배열 목데이터만 사용)라 "레거시 데이터 마이그레이션"은 불필요했지만, 사용자는 명시적으로 "마이그레이션 작성"을 요청했다. `CREATE TABLE IF NOT EXISTS` 한 줄로도 지금 당장은 충분히 동작하지만, 그렇게 하면 향후 스키마가 바뀔 때마다(예: 컬럼 추가) 기존 설치본에서 안전하게 적용할 방법이 없다.

## Action

`PRAGMA user_version`을 읽어 현재 버전보다 높은 마이그레이션만 순서대로 `execAsync`로 적용하고 버전을 올리는 러너를 작성했다(`app/src/db/migrations.ts`). 마이그레이션은 `{version, sql}` 배열로 정의하고, 앱 시작 시(`SQLiteProvider`의 `onInit`) 매번 실행하되 이미 적용된 버전은 건너뛰므로 idempotent하다. 구현 중 §7 초안 스키마만으로는 `CardContent`가 카드를 렌더링할 수 없다는 걸 발견해(video/text 구분 불가, 채널 핸들 필드 없음) `kind`/`channel`/`progress` 컬럼을 마이그레이션 1에 추가로 포함시켰다.

## Result

- 첫 마이그레이션이 곧 "최초 버전"이라는 점을 명확히 문서화해 혼선 방지(PROJECT.md §7에 "위 §7 초안에 없던 컬럼" 각주 추가)
- 향후 스키마 변경은 `MIGRATIONS` 배열에 새 항목을 추가하는 것만으로 기존 설치본에 안전하게 반영 가능 — 지금 당장 필요는 없지만 확장 비용이 거의 0
- 실기기 재설치 테스트에서 마이그레이션이 크래시 없이 적용되고, 재실행해도 스키마 재생성을 시도하지 않는 것을 로그로 확인

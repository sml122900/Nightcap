# 유입 경로를 자동 스캔 → 공유시트로 전환, 홈/정리 화면 분리

## Problem

W3-1까지는 스크린샷 자동 스캔(`TriageScreen` 마운트/포그라운드 시 `scanNewScreenshots` 실행)이 유일한 유입 경로였다. 도그푸딩 결과, 전체 스크린샷을 무조건 스택에 밀어넣는 방식은 업무 캡처·일회성 스크린샷까지 정리 대상으로 만들어 "정리가 숙제가 되는" 문제를 낳았다. 애초에 코어 루프(§1)는 "의도적으로 캡처한 콘텐츠를 정리"하는 것이지 "찍은 모든 스크린샷을 정리"하는 게 아니었다.

또한 유입 경로를 공유시트로 바꾸면서 "공유 수신 시 앱이 열리면 토스트만 띄우고 정리 모드로 바로 진입하지 않는다"는 요구가 나왔는데, 기존 구조에선 `TriageScreen`(스와이프 UI)이 앱의 유일한 기본 화면이라 "정리 모드가 아닌 착지 지점"이 존재하지 않았다.

## Action

- 유입 경로를 공유시트(`expo-share-intent`, 주 경로) / 자동 스캔(설정 토글, 기본 OFF) 두 가지로 재구성. 둘 다 같은 `captures` 스키마로 수렴하고, `services/shareIntake.ts`가 사본복사·DRM 판별 로직(`services/screenshotScan.ts`의 `copyToSandbox`/`isLikelyDrm`)을 그대로 재사용한다.
- 공유시트 이미지 경로는 `asset_id`가 없어 파일 SHA-256 해시(`content_hash` 컬럼, migrations v3의 부분 유니크 인덱스)로 재공유 dedup을 대신한다.
- 앱의 기본 화면을 `TriageScreen`(스와이프 UI)에서 별도의 `HomeScreen`(오늘 담은 개수 + "정리 시작" 버튼)으로 바꿨다. `App.tsx`의 `Screen` 유니언에 `'home'`/`'settings'`를 추가하고, 공유 수신은 `RootNavigator`에서 `useShareIntent()`로 항상 수신해 홈으로 이동 + 토스트만 띄운다. PROJECT.md §4의 "홈 (오늘의 스택)" 화면 명세가 원래 있었으나 구현이 `TriageScreen`과 합쳐져 있었던 것을 이번에 분리했다.
- `TriageScreen` 상단바 "닫기"가 기존엔 데모 리셋(`resetDemoData`)을 호출했는데, 이제 홈이 별도로 있으므로 "닫기"는 `onExit`(홈으로 복귀)를 호출하도록 바꿨다. 미판정 캡처는 DB에 그대로 남아 다음에 "정리 시작"을 누르면 다시 나타난다. 데모 리셋은 `DoneScreen`의 "다시 시작" 버튼에만 남겼다(개발용, 이번 범위 밖).

## Result

- 자동 스캔 기본 OFF라 신규 설치 시 사진 라이브러리 권한 프롬프트가 뜨지 않음(공유시트 경로는 권한 불필요) — 온보딩 마찰 감소가 부수 이득.
- 홈/정리 화면 분리로 "공유 수신 → 토스트 → 홈"과 "유저가 명시적으로 정리 시작"이 분리돼, 낮의 흐름과 밤의 정리 세션이 다시 명확히 구분됨.
- `content_hash`/`asset_id` 두 개의 부분 유니크 인덱스가 각자 다른 유입 경로의 dedup을 담당 — 서로 간섭하지 않음(둘 다 NULL 허용, SQLite는 NULL을 유니크 제약에서 구분되는 값으로 취급).

# 실기기 수동 검증 체크리스트

빌드/설치는 자동으로 확인되지만 "기능이 실제로 동작하는가"는 눈으로 봐야 아는 항목들. 밀린 것들을
리빌드 1회로 한 번에 소화한다.

**순서를 지킬 것.** ①이 실패하면 ②③ 결과가 전부 무의미하다(온보딩을 못 지나면 그 뒤 화면에
도달하지 못한다).

## 빌드

```powershell
$env:TMP='C:\tmp_expo'; $env:TEMP='C:\tmp_expo'; $env:GRADLE_USER_HOME='C:\gradle_home'
```
(한글 사용자 경로 때문에 필수 — `docs/troubleshooting/non-ascii-user-path-breaks-prebuild-and-gradle.md`)

`expo prebuild` → `gradlew assembleRelease` → `adb install -r`. **`am start` 금지** — 실행은 손으로.

**릴리즈 빌드로 검증하는 이유**: debug APK는 JS 번들을 Metro에서 받아오므로 USB(또는 무선 ADB)가
붙어 있어야만 뜬다. ②의 공유시트 흐름은 다른 앱에서 공유해 앱이 콜드 스타트되는 시나리오라
케이블을 달고 하면 부자연스럽고, Metro에 못 닿는 순간 그냥 빨간 화면이 된다. 릴리즈는 번들이
APK에 박혀 있어 완전히 독립적이다. 릴리즈 서명은 `signingConfigs.debug`로 잡혀 있어(RN 템플릿
기본값, `android/app/build.gradle`) 별도 키스토어 설정이 필요 없다.

**릴리즈에서 달라지는 것**: `__DEV__`가 false라 설정 화면의 개발자 통계 섹션이 자동으로 안 뜬다.
→ **설정 화면 맨 아래 `nightcap 1.0.0` 라벨을 5번 탭**하면 열린다(도그푸딩을 릴리즈로 하려고
만든 게이트라 의도된 동작).

**릴리즈로 하면 안 되는 것**: `bg` 값 비교(아래 "보류 중인 결정")는 값 하나 바꿀 때마다 재빌드라
릴리즈에 안 맞는다. 무선 ADB(`adb tcpip 5555`) + dev client로 따로 볼 것.

- [ ] **공유 카드가 라이트 모드에서도 다크로 출력되는지** — 화면 미리보기와 저장된 PNG 둘 다

### ③-1 이번 리페인트에서 새로 생긴 위험 지점

토큰 치환이 로직을 안 건드렸어도 "값이 뒤집히는" 자리는 눈으로 봐야 안다.

- [ ] **반전 버튼** — 완료 요약의 "보관함 보기", 보관함 필터 칩 선택 상태. 배경이 `textPrimary`,
      글자가 `bg`라 라이트에서 검정 배경 + 흰 글자가 된다. 글자가 사라져 보이면 토큰이 틀린 것
- [ ] **골드 위 글자** — 완료 요약 히어로 블록, "정리 시작"/"이미지로 공유" 버튼.
      라이트 골드(#C99400)에 흰 잉크(`onAccent`)가 얹힌다
- [ ] **판정 오버레이가 카드를 덮지 않는지** — 스와이프 중 보류(파랑)/삭제(빨강)/별점(골드) 딤이
      깔릴 때 카드 내용이 비쳐야 한다. 불투명하게 덮으면 `*Scrim` 대신 `*Muted`가 들어간 것
- [ ] **커버 위 별점 배지** — 보관함 그리드. 라이트 모드에서도 배지 안 골드가 선명해야 한다
      (배지는 테마와 무관하게 시네마로 칠한다)
- [ ] **터치 타겟 44pt** — 휴지통 "복원", 보관함 필터 칩, 보관함 상세 "링크 해제",
      정리 화면 하단 ←↓↑→ 버튼. 눌러서 반응하는지 + 커진 높이 때문에 레이아웃이 깨지지 않았는지
- [ ] **별점 표기 통일** — 보관함 그리드 배지 / 보관함 상세 / 공유 카드 셀. 셋 다 `★ N.N` 형식
- [ ] **글꼴 크기 확대** — OS 설정에서 글꼴을 최대로 키우고 정리 화면·완료 요약. 1.4배에서 멈춰야
      하고 카드/별점 바가 화면 밖으로 나가면 안 된다
- [ ] **🔗 링크 포함 라벨** — 칩 토큰으로 바뀌었다. 라이트에서 배경(`accentMuted`)과 글자(`accent`)
      대비 확인
- [ ] **빈 상태 3곳** — 보관함 비었을 때 / 휴지통 비었을 때 / 정리할 카드 0개. 톤이 같아야 한다

## 보류 중인 결정

### `bg`: `#000000` vs `#0B0D12`

현재 코드는 `#0B0D12`(디자인 시스템 지시서 값). 순수 검정으로 되돌릴 근거가 더 세다는 판단이 나온 상태:

- OLED 배터리 — 밤에 오래 켜두는 앱이다
- 스크린샷 콘텐츠의 명암비 — 커버가 화면 대부분을 차지한다
- 층위 구분은 `surface`(#14171F)가 이미 하고 있어서 `bg`만 순수 검정으로 내려도 위계가 안 무너진다

반대급부는 순수 검정의 스크롤 잔상(OLED smearing). **실기기에서 두 값을 눈으로 비교해 결정한다.**
시네마 `bg`(#08090C)도 같이 판단할 것. 결정 전까지 코드는 건드리지 않는다.

### 추출색 클램프(`app/src/theme/colorClamp.ts`)의 소비자

만들어뒀지만 지금 아무도 안 쓴다. 원래 후보였던 **보관함 셀 틴트는 무의미하다** — 셀에 커버 이미지가
꽉 차서 틴트가 보이지 않는다.

쓸 자리는 **LibraryDetail 메타 영역 배경** 하나. 이미지 아래 영역이 커버 색을 옅게 받으면
시네마↔테마 경계가 훨씬 자연스러워진다(위 ③에서 미검증 리스크로 잡아둔 바로 그 경계).

테스트 있는 순수 함수라 유지 비용이 0이므로 코드는 남긴다. **경계를 눈으로 보고 어색하면 그때 붙인다.**

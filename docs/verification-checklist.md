# 실기기 수동 검증 체크리스트

빌드/설치는 자동으로 확인되지만 "기능이 실제로 동작하는가"는 눈으로 봐야 아는 항목들. 밀린 것들을
리빌드 1회로 한 번에 소화한다.

**순서를 지킬 것.** ①이 실패하면 ②③ 결과가 전부 무의미하다(온보딩을 못 지나면 그 뒤 화면에
도달하지 못한다).

## 빌드

```powershell
$env:TMP='C:\tmp_expo'; $env:TEMP='C:\tmp_expo'; $env:GRADLE_USER_HOME='C:\gradle_home'
```
(한글 사용자 경로 때문에 필수 — `docs/troubleshooting/non-ascii-user-path-breaks-prebuild-and-gradle.md`)

`expo prebuild` → `gradlew assembleDebug` → `adb install -r`. **`am start` 금지** — 실행은 손으로.

## 보류 중인 결정

### `bg`: `#000000` vs `#0B0D12`

현재 코드는 `#0B0D12`(디자인 시스템 지시서 값). 순수 검정으로 되돌릴 근거가 더 세다는 판단이 나온 상태:

- OLED 배터리 — 밤에 오래 켜두는 앱이다
- 스크린샷 콘텐츠의 명암비 — 커버가 화면 대부분을 차지한다
- 층위 구분은 `surface`(#14171F)가 이미 하고 있어서 `bg`만 순수 검정으로 내려도 위계가 안 무너진다

반대급부는 순수 검정의 스크롤 잔상(OLED smearing). **실기기에서 두 값을 눈으로 비교해 결정한다.**
시네마 `bg`(#08090C)도 같이 판단할 것. 결정 전까지 코드는 건드리지 않는다.

### 추출색 클램프(`app/src/theme/colorClamp.ts`)의 소비자

만들어뒀지만 지금 아무도 안 쓴다. 원래 후보였던 **보관함 셀 틴트는 무의미하다** — 셀에 커버 이미지가
꽉 차서 틴트가 보이지 않는다.

쓸 자리는 **LibraryDetail 메타 영역 배경** 하나. 이미지 아래 영역이 커버 색을 옅게 받으면
시네마↔테마 경계가 훨씬 자연스러워진다(위 ③에서 미검증 리스크로 잡아둔 바로 그 경계).

테스트 있는 순수 함수라 유지 비용이 0이므로 코드는 남긴다. **경계를 눈으로 보고 어색하면 그때 붙인다.**

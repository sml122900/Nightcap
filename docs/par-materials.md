## React Native 제스처 엔진을 프로토타입 스펙 그대로 이식

**Problem**: 웹 프로토타입(vanilla JS/CSS)에 이미 검증된 스와이프 물리 값(임계값, 회전 계수, 스프링 커브)이 있었고, 이를 React Native(Reanimated + Gesture Handler)로 옮기면서 "손맛"을 그대로 재현해야 했다. 이후 제스처 체계 자체가 3방향(keep/drop/five)에서 4방향(보류/이전/삭제/별점모드)으로 전면 개편되는 요구사항 변경도 있었다.

**Action**: 프로토타입의 임계값·수식(upness/downness 분리, 프리필 공식)을 상수 파일로 격리해 코드와 스펙 문서(PROJECT.md)가 항상 대조 가능하게 만들었다. 드래그 중인 카드와 퇴장 애니메이션을 별도 컴포넌트로 분리해 연속 스와이프 시 다음 카드가 즉시 승격되도록 설계. 별점 모드는 도킹 애니메이션 + 0.5단위 별바 드래그를 Reanimated worklet과 `measure()`로 구현.

**Result**: 3방향→4방향 전면 개편을 기존 아키텍처(상수 격리, 퇴장 컴포넌트 분리)를 재사용하며 물리 엔진 파일은 건드리지 않고 이전/재작성 범위를 최소화. 타입체크·expo-doctor 통과, 실기기에서 크래시 없이 동작 확인.

## SQLite 기반 영속화 + 소프트 삭제 휴지통 설계

**Problem**: 메모리 배열 목데이터만 쓰던 앱에 처음으로 실제 데이터 영속성이 필요했고, "삭제"가 단순 배열 제거가 아니라 7일 유예 휴지통 + 세션 종료 시 사진첩 일괄 삭제 + 강제종료 후에도 삭제 큐가 유실되지 않아야 하는 복합 요구사항이었다.

**Action**: 버저닝된 마이그레이션 시스템(PRAGMA user_version)과 소프트 삭제(deleted_at) 컬럼으로 스키마를 설계. 사진첩 일괄 삭제 함수를 "이번 세션의 drop만"으로 좁히지 않고 "아직 asset이 남아있는 모든 drop 행"을 대상으로 일반화해, 세션 종료 트리거와 강제종료 복구 트리거가 같은 함수 하나를 공유하도록 만들었다.

**Result**: 별도의 "재시도 큐" 테이블이나 상태 플래그 없이, 쿼리 조건 하나로 정상 종료와 강제종료 복구를 모두 처리하는 단순한 설계로 귀결. 구현 전 계획을 서브에이전트로 교차검증해 스키마 필드 누락(kind/channel 컬럼)과 잠재적 자기모순(휴지통 쿼리가 목데이터에서 영구히 비는 문제)을 코드 작성 전에 발견해 재작업 없이 반영.

## 최신 SDK 문서 확인으로 런타임 폐기 API 사전 회피

**Problem**: 자주 바뀌는 Expo SDK에서 흔한 예제 코드(`deleteAssetsAsync`, `FileSystem.deleteAsync`)를 그대로 썼다면, 컴파일은 통과하지만 실기기에서 크래시가 나는 상황이었다(SDK57에서 구 API가 런타임 예외로 하드 폐기됨).

**Action**: 코드 작성 전 설치된 패키지의 실제 타입 선언(.d.ts)과 공식 버전별 문서를 직접 확인해, 클래스 기반 신규 API(`MediaLibrary.Asset.delete`, `new File(uri).delete()`)로 처음부터 정확하게 구현.

**Result**: 런타임에야 발견됐을 크래시를 구현 단계에서 회피, 추가 디버깅 사이클 없이 한 번에 정상 동작.

## 실제 스크린샷 스캔 파이프라인을 첫 렌더 차단 없이 통합

**Problem**: MediaLibrary 스캔·파일 복사·DRM 판별을 포함한 캡처 파이프라인은 느릴 수 있는 I/O 작업이 여러 단계 얽혀 있는데, 이를 앱 시작 초기화(`SQLiteProvider.onInit`)에 그대로 넣으면 스캔이 끝날 때까지 첫 화면 자체가 뜨지 않는 문제가 생긴다. 게다가 스캔 도중 사용자가 스와이프 중이거나 별점 모드를 쓰고 있으면, 새로 스캔된 카드가 그 상태를 깨뜨리지 않고 끼어들어야 했다.

**Action**: 스캔을 `initDb` 체인에서 제외하고 화면 마운트 이후 비동기로 실행하도록 분리했다. 스캔 결과는 기존 스택을 통째로 교체하지 않고, 진행 중인 카드/카운터를 건드리지 않는 append-only 병합으로 큐 꼬리에만 추가했다. 드래그·별점 모드 진행 여부를 ref로 추적해, 진행 중이면 병합을 대기열에 넣어뒀다가 제스처가 끝나는 순간 flush하도록 만들었다.

**Result**: 스캔이 아무리 오래 걸려도 앱 첫 화면 로딩 속도에 영향이 없고, 사용자가 스와이프 도중 새 스크린샷이 몰래 끼어들어 카드가 밀리거나 진행률이 튀는 일이 없어졌다. 실패 허용 설계(watermark를 실패 지점 이전으로 유지)까지 더해 강제종료·부분권한 상황에서도 재시도가 자동으로 되도록 구성.

## AGP 버전 조건부 dead code로 인한 서드파티 라이브러리 빌드 실패를 config plugin으로 영속 수정

**Problem**: DRM 판별용으로 추가한 `react-native-image-colors`가 최신 Android Gradle Plugin(8+) 환경에서 자체 Kotlin/Java JVM 타깃 설정 코드가 조건부로 무시되면서 릴리즈 빌드 자체가 실패했다. `expo prebuild`가 네이티브 프로젝트를 매번 통째로 재생성하는 구조라, 생성된 파일을 직접 고쳐도 다음 빌드에서 사라지는 제약도 있었다.

**Action**: 실패 원인을 라이브러리의 `build.gradle` 소스까지 직접 추적해 "AGP<8에서만 적용되는 죽은 코드"라는 걸 확인했고, 루트 빌드 스크립트에 모든 서브프로젝트의 JVM 타깃을 강제하는 보정 로직을 추가했다. 처음엔 `afterEvaluate`로 시도했다가 `--configure-on-demand` 하에서 "이미 평가된 프로젝트" 예외를 만나, 평가 시점에 의존하지 않는 `pluginManager.withPlugin`/`tasks.withType` 방식으로 재작성했다. 이 로직은 생성된 `android/build.gradle`에 직접 넣지 않고, `expo prebuild`가 재실행돼도 자동 재적용되는 로컬 config plugin으로 만들었다.

**Result**: 코드 한 줄 건드리지 않고 서드파티 의존성의 구조적 결함을 프로젝트 차원에서 흡수하는 재사용 가능한 픽스를 만들어, 향후 같은 유형의 라이브러리를 추가해도 같은 실패가 재발하지 않도록 했다.
